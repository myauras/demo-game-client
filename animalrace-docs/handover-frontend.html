只能記三件事的話

  1. 前端只播放伺服器給的結果。演出從結果反推，衝線順序必須等於名次，出包者不能看起來快贏了。
  2. 狀態更新不要掛在動畫或 requestAnimationFrame 上。背景分頁會凍結動畫，已經因此出過珠盤空格。
  3. 一個畫面狀態只給一種下注手勢；暫存單封盤即作廢的問題至少要做「未確認強警示」。

必改 3 項

F01

前端只能播放結果，不能決定或計算結果

必改
Demo 現況
Demo 前端同時負責輪次推導、賽果抽定（透過轉接層）、賠率蒙地卡羅、結算與錢包。這是因為沒有後台。
正式版
正式版前端只收伺服器的 round 封包和 outcome 向量。結算金額、餘額、賠率、熱門分組都以伺服器下發為準，前端不重算。卡上的 🔥／❄ 徽章與路子冷熱頁也改讀伺服器的分組，不要自己用屬性算。
出處
規格 §10.3「前端不持有任何影響結果的邏輯」
F02

上線前要拔掉的 Demo 工具和假功能

必改
Demo 現況
  • 連點餘額 5 次重置錢包（game.js 第 712 行）
  • log 頁底部「🔄 重置錢包（Demo）」鈕
  • log 頁「回報」是假按鈕，order id 是前端隨機派生
  • 他人下注流、中獎跑馬燈是 ambience.js 捏造的
正式版
重置功能移除；回報、單號、下注流、跑馬燈改接後端真實資料。捏造的中獎播報不能上線。
出處
js/game.js、js/log-ui.js、js/ambience.js
F03

不要搬 Math.random 劫持和種子重放這兩個技巧

必改
Demo 現況
adapter-b.js 一載入就把全域 Math.random 換成調度器，呼叫 mock-server 時臨時塞入「局號種子」亂數，所以它必須比 mock-server-b.js 先載入。路子歷史也是開機時用種子把整靴 200 局重放出來。
正式版
這兩招只為了在沒有伺服器的情況下讓各裝置結果一致。正式版有伺服器就整層刪掉，歷史改讀 API。
出處
js/adapter-b.js 檔頭；README 載入順序段

留意：踩過的坑與使用者裁決 11 項

F04

演出是從結果反推的，有兩條不能破的鐵則

留意
Demo 現況
race-fx.js 拿到 outcome（名次、出包旗標、出包位置 out_at）後反推 10 秒跑動：名次決定衝線時刻，屬性×賽段決定速度曲線形狀。鐵則一：衝線順序必須等於名次。鐵則二：出包者不能看起來快贏了——出包時刻取「領先者通過該點的時間 ×1.07 再加 140ms」。內建 RaceFX._verify(n) 會連跑 n 局檢查曲線單調、衝線順序、出包時點。
正式版
換引擎重做畫面時，演出公式可以重寫，但保留這兩條鐵則和一個等效的自動檢查器。出包演出 1.2–1.5 秒、奪冠 0.8–1.2 秒、派彩入帳動畫 0.4 秒不可省（企畫書 §1.2）。
出處
js/race-fx.js；B07 回報；B09 驗收 _verify(12) 零違規
F05

時間軸要從時間推導，不要用計時器一段接一段

留意
Demo 現況
引擎每次都從時間算出「現在第幾局、哪個階段、剩幾毫秒」，所以中途打開頁面會直接接上正在跑的比賽、重整不重播、休眠醒來自動補上漏掉的局。
正式版
正式版改成「伺服器時間 + 本機時差」推導，概念不變。不要用 setTimeout 串階段——分頁被節流或手機鎖屏就會漏拍。斷線重連要回到當前狀態，不重播演出。
出處
js/round-engine.js 檔頭；規格 §10.3
F06

背景分頁會凍結 requestAnimationFrame，資料更新不能掛在動畫上

留意
Demo 現況
踩過兩次。B06：「捲到最新」原本寫在 rAF 裡，隱藏分頁時被凍住；改成同步執行。B10：珠盤偶發空格，根因是安全網補結算的局沒寫入賽果紀錄，加上落珠靠動畫插入 DOM；修法是 DOM 插入改事件驅動、動畫只疊加，並加 healShoe() 在結算後、回補後、回到前景時比對珠數與紀錄數自我修復。
正式版
原則：狀態與 DOM 的更新永遠同步完成，動畫只是裝飾。關鍵列表（路子、注單、log）加一個「顯示數＝資料數」的自癒檢查。
出處
js/roads-ui.js；TASKS-B 2026-09-03 B10-R2 條目
F07

休眠期間補結算的局，自動下注要自己對帳

留意
Demo 現況
分頁休眠時引擎會靜默補結漏掉的局，不發一般事件。B10 初版因此漏記損益，停利停損判定卡住，還多放了單。修法是維護「已放單未入帳」清單，每個事件前先從注單歷史補記。休眠期間不補放單（掛機的意思是 App 開著才下）。
正式版
App 退到背景再回來同樣會遇到。若自動下注留在前端，照這個模式做；若改由伺服器排程，前端只顯示伺服器狀態。
出處
js/autobet.js 檔頭；規格 §6.1 自動下注段
F08

拖曳捲動不要用 setPointerCapture

留意
Demo 現況
路子容器是隱藏捲條的拖曳平移。setPointerCapture 會把 click 的目標劫持到容器，珠盤的「點擊切換模式」就收不到事件（路子模擬器踩過）。正確做法：pointerdown 掛在容器，pointermove／pointerup／pointercancel 掛在 window；位移超過 5px 判定為拖曳，並在捕獲階段吞掉接下來的 click。切頁籤後要等面板顯示了才捲到最新，隱藏時 scrollWidth 取不到。
正式版
引擎端的捲動元件通常內建處理，但同樣要確認「拖完不誤觸點擊」。
出處
規格 §7.5
F09

手機上不要出現原生捲條

留意
Demo 現況
B08 加了嵌條之後，卡片區退化出可見的直向捲條，使用者直接退回。之後全 UI 捲條隱藏、觸控捲動保留；所有面板內容超高時在面板內部捲動，不准整頁溢出。
正式版
每次改版面都做一次全畫面掃描：只允許指定的捲動容器、body 零橫向溢出。
出處
TASKS-B 2026-09-03 B08-R2 條目
F10

一個畫面狀態只給一種下注手勢

留意
Demo 現況
B05 修了三輪才定案「頁籤定模式」：頁籤決定唯一可點的下注動作。冠軍、出包頁籤點整張卡＝以當前籌碼成注；前二連點兩張卡，第二張點下即成注；特殊頁籤是四列面板點鈕成注。展開屬性統一走卡右上 ▾。早期卡上同時有「勝／包」小按鈕和頁籤，使用者會誤點。
正式版
重做 UI 時維持「點卡＝下注、▾＝展開」這組手勢，不要在卡上再加第二個下注入口。展開動畫只在使用者手點時播放，切頁籤或重繪不重播。
出處
規格 §2、§9；TASKS-B B05-R3、B06-R2、B10-R2 條目
F11

暫存單在封盤瞬間作廢，同事下了大注沒按確認

留意

正式版
最低限度做 D1＋D4：剩 5 秒時確認鈕強烈脈動並跳「注單尚未確認」、作廢時明確告知幾注未送出；確認鈕帶金額「確認下注 1,500」。D2（點卡即成注＋5 秒撤銷）留移植時 A/B 測試。D3 封盤自動送出不採（未經同意扣款有合規疑慮）。
