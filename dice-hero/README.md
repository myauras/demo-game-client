# 骰子勇者 · Dice Hero H5 demo

直接以瀏覽器開啟 `index.html` 即可遊玩，無建置或安裝需求。直式手機版面，桌面置中顯示。

也可在此資料夾以 `python -m http.server 4173 --bind 127.0.0.1` 啟動，瀏覽 `http://127.0.0.1:4173`。

## 規格來源

規則於 2026-11-17 以問答方式定稿，之後依試玩意見持續調整；企劃全文與決策紀錄沒有放進這個 repo，現行規則以本文件和 `js/game.js` 開頭的 `CONFIG` 為準。純 HTML＋CSS＋原生 JavaScript，無建置、無套件；規則與畫面流程分兩支 JS，規則附 node 測試。資料夾分法比照同 repo 的 hotdrop、emperor（`css/`、`js/`、`test/`）。

玩法摘要：玩家是一顆在無限地圖上翻滾的骰子，每翻一步花一次底注，朝上點數照實體骰子的幾何變化。點數要大於怪物點數才打贏（平手算輸）；怪物是 1～5 點，獎金照點數給：2／3／6／10／30 倍（點數蓋著的黑色怪物各乘 1.5），分小怪（1～2 點）、菁英（3～4 點）、BOSS（5 點）三檔，越高檔打輸被擊退得越遠（小怪退回上一格、菁英再多退 1 格、BOSS 再多退 2 格）。寶箱標「大」要 4～6 點、標「小」要 1～3 點，分木箱 4 倍、鐵箱 6 倍、金箱 10 倍三檔，木箱最多試 3 次、鐵箱和金箱最多試 2 次，獎池越滿鐵箱和金箱越容易出現。隨機藥水喝下去隨機得到祝福或詛咒（各半，兩者互相取代）；毒潭踩上去就中毒，踩過不會消失；重骰地塊踩上去骰子重新骰一次，可以走開再踩回來一直重骰。打輸或開不了就被彈回去並重骰。走遠之後，後面的目標會收走，新的只補在視野外；沒有每波倒數，只有換注和傳送會把周圍整批換掉。

地圖：河流是跨區塊的長河（14～22 格，約三成帶一條支流）；森林是 8～13 格的一整片；山脈中間留一格隘口，分成一大一小兩座。三面被山、河、森林包住的死角留給 BOSS 和金箱。鄉村和城鎮是地圖上固定的地標（每 24×24 格一個），旁邊鋪一段麥田，目前沒有作用。

## Demo 假設

- 亂數使用 `Math.random()`，供互動原型使用。地形另用固定演算法由區域種子產生，同一區域走回去地形不變。
- 初始 1,000 模擬點數，底注 10／20／50／100。無金流、帳戶、伺服器或真實獎品。
- 點數不夠走一步時才能按「補點數」，補回 1,000。
- RTP 目標 95%。由幕後的獎池控制：每步步費的 95% 進獎池，派彩從獎池扣；場上的怪物和寶箱總額不超過獎池，付不起的就先不擺（那格留空），等獎池回來再補。畫面上不顯示獎池。
- 本機儲存模擬點數、獎池、底注與美術風格；若瀏覽器禁止儲存，當次仍可操作。重新整理頁面後地圖與骰子重新開始，身上的狀態不保留。多分頁沒有共享狀態鎖，請以單一分頁體驗。
- 不含音效、自動走、加速、橫式版面、多語系、新手教學。

## 操作方式

- 點骰子上下左右相鄰的虛線格往那邊翻一格，按住會一直走；桌面可用方向鍵或 WASD。
- 畫面只看得到骰子的頂面和前面。祝福或詛咒的 ±1 顯示在上方狀態列和骰子右上角。
- 底注：點其他額度會先跳警告，確認後地圖立刻刷新（目標和山、河、森林都換一批）；換注後要再走 10 步（或踩到傳送）才能再換，期間其他額度顯示鎖頭，左邊顯示「再 N 步可換」。
- 「規則」開啟規則說明與獎金表；「風格」切換幾何極簡與像素風。
- 只有打贏 BOSS 和開出金箱會播大獎演出，點一下可跳過。
- 在本機（`localhost`）開啟時會有測試用的 `window.DiceHeroDebug`（可從主控台讀寫遊戲狀態）；放上網站的版本沒有。

## 程式檔案

- `index.html`：頁面骨架
- `css/style.css`：直式版面、透視地圖、立體骰子、兩種美術風格與動畫
- `js/game.js`：規則。骰子翻滾、地形產生、目標擺放與隨走隨補、怪物與擊退／寶箱／藥水／毒潭／重骰結算、鄉村城鎮與麥田、狀態、傳送、換注與換注鎖、獎池。所有可調數值集中在開頭的 `CONFIG`
- `js/app.js`：畫面流程。把 `js/game.js` 回傳的事件依序演出，處理操作、彈窗、本機儲存
- `test/game.test.cjs`：規則驗證，在這個資料夾以 `node test/game.test.cjs` 執行（含一段 RTP 模擬，約需一分鐘）
- `test/sim.cjs`：機器人 RTP 模擬，以 `node test/sim.cjs [步數] [種子]` 執行。機器人有亂走、憑感覺玩（另有不打 BOSS、只打小怪兩種）、會算的、會算＋衝傳送點、會算＋換注搭配傳送；最後另外印出憑感覺玩時各檔怪物的不虧本比例

## RTP 模擬結果

目前數值下每種機器人 3 萬步、單一亂數種子（2026-11-25 重跑）：憑感覺玩 95.1%、憑感覺但不打 BOSS 95.0%、憑感覺只打小怪 92.5%、會算的 95.2%、衝傳送點 95.3%、換注搭配傳送 95.2%、亂走 12.4%。

只打小怪拿不滿 95%：小怪的獎金只夠補路費，要打菁英和 BOSS 才領得完獎池裡的錢，所以 RTP 跟玩法有關。亂走很低是因為會反覆踩毒潭，而且沒有不看點數就能拿的獎。

開局偏高：開場獎池有 115 倍底注，前幾百步領到的比長期多。憑感覺玩前 50／200／1000 步是 106.5%／106.1%／98.6%（300、300、100 個種子平均）；會算骰面的玩家前 200 步約 130%、平均多拿約 600 點（底注 10），前 1000 步約 102%，長期仍是 95%。這組開局數字比早期版本高（當時憑感覺玩約 97%、會算的 113～122%），原因沒有逐項拆解，開場獎池可能需要重新調。

憑感覺玩時各檔怪物「不虧本擊殺」的比例（從第一次出手到打贏花的步費不超過獎金；中途放棄算虧；三個種子）：小怪 95～96%、菁英 81～85%、BOSS 70～72%。高獎金的怪由獎池決定擺不擺得出來，所以菁英和 BOSS 比較少見。

「會算的」機器人不保證是理論上最強的玩法；長期 95% 的上限來自獎池的帳（`test/game.test.cjs` 驗證獎池不透支），不依賴機器人夠不夠聰明。

## 圖片處理方式

沒有使用任何圖檔。幾何風的圖示是程式內的向量路徑，像素風的圖示是程式內的 8×8 點陣，骰子是 CSS 3D 立方體。美術與介面為原創，未使用其他遊戲的名稱、角色或美術。
