一、驗證方法與判準

以 Node 載入與瀏覽器完全相同的 tables-b.js / mock-server-b.js。每輪經真實接口 newRound（含規格級蒙地卡羅賠率反推）開局，再以 mock-server 測試鉤 _draw（與正式開獎同一支 drawVector）對同一輪參數抽 5,000–10,000 次賽果、對全部 45 個盤口結算——賠率所依據的分佈與開獎完全同源。瀏覽器 sim.html 留作互動抽查（MC 選項已補 1,000,000 規格檔）。
RTP 判準：|實測 − 檔位| ≤ max(0.1pp, 3σ)。σ 以「輪」為單位計算（同輪內共用賠率表、樣本相關，逐抽計 σ 會低估）。檔位依 Q9 裁決：冠軍 95／前二連 95／出包 94／零出包 94。
取整對帳：規格 §6.2 取整一律向莊家（捨去至小數兩位）、微幅收益計入總 RTP 對帳——低賠率盤口有可計算的確定性損耗（賠率 o 平均損 0.005，RTP 損 ≈ 0.5×命中率 pp），對帳欄明列。
自洽驗證：全程 6,000 輪的「封包重建參數 → 賠率快取比對」0 筆不符；24/24 次抽驗改走真實 placeBets→lockRound→settleRound 路徑，派彩與獨立判定完全一致。

三、防套利窮舉（工作項 2）——本遊戲最容易出包的地方

3.1 組合層：任意複押組合無 EV>100%

結算對每注獨立計算 floor(amount × odds)、下注不影響賽果，故任意跨注別複押組合的 EV 是各單注 EV 的注額加權平均——不存在任何組合能超過其中單注的最大 EV（對沖只能降波動、不能造出期望值；整數取整只會更利莊家）。窮舉因此歸結為 45 個單一盤口的逐一檢驗：上節實測全部 < 100%（最高 95.20%）。長期面通過。

3.2 逐輪層：知情玩家掃描（發現問題 → 已修正）

屬性、心情、賽段全數公開（公平性揭露），玩家可自跑高精度模擬還原各盤口真實命中率、只挑賠率開高的輪下注。掃描方式：250 輪，每輪以獨立 50–100 萬次同源抽樣重估 45 個盤口真實機率，計算「當輪賠率 × 真實機率」：

賠率反推 MC 次數EV>100% 盤口顯著（z>2）高度顯著（z>3）單盤最高 EV選注策略邊際
100,000（B03 誤讀值）87 / 11,250（0.77%）125108.9%（前二連 2-7，z=7.0）+0.44% / 輪
1,000,000（規格 §6.2）1 / 11,25000101.2%（z=0.75，統計上與噪音無異）+0.005% / 輪（贏家詛咒噪音內）

根因：稀有前二連盤口命中率低至 0.2–3%，10 萬輪 MC 的相對噪音 ±3–7%——噪音一旦吃掉 5% 莊家邊際，該輪賠率就「開高」。翻正的 87 個盤口全部是前二連、無一冠軍/出包/零出包（後者機率高、噪音小）。100 萬輪後 3σ 噪音壓進邊際內；殘餘暴露僅極端尾部（p<0.3% 且未觸封頂的組合），量級 <0.01%/輪且不可被穩定識別。結構性零噪音方案（解析式聯合分佈枚舉定價）列第七節待裁決。
