§1 產品定位與主題 決議①

8 隻 Q 版動物跑障礙賽的全服同步輪次觀賽投注遊戲。玩家不操作賽事、只在開賽前下注；核心賣點是「看得懂的讀盤」──鴨子會游泳、豹跑得快是常識，賽段組成與心情徽章把判斷素材直接攤在下注畫面上。調性：歡樂・爆笑・全民看得懂（圓潤 Q 版、粗描邊、誇張表情；出包走喜劇路線）。避免：寫實動物、血腥、賭場金碧輝煌感。

§2 輪次結構 決議⑧

全服同步、每 40 秒一輪的固定循環（v1.3：下注窗由 15s 延長至 25s，緊張感改由末 5 秒倒數演出製造）。所有玩家看到同一場比賽、同一份賽果；輪次不論是否有人下注照常進行並記錄進路子。

下注階段00:00–00:25（25s）
封盤2s
賽事演出00:17–00:27（10s）
結算3s

封盤段含發車倒數；結算段含派彩演出與下輪動物數值／賽段／心情的生成揭示。

  • 下注階段（25s）：展示本局賽段組成、8 張動物卡（精簡卡＋點卡展開屬性／統計，v1.3）；演出區顯示路子總覽（§7.1）。四注別採頁籤定模式（v1.3；v1.6 頁籤改冠軍/前二連/出包/特殊）：頁籤決定唯一可點的下注動作（冠軍/出包＝單一大按鈕、前二連＝整卡配對兩點成注、特殊＝四列面板點鈕成注），可複押多注別並存注單列。末 5 秒倒數壓迫演出。
  • 封盤（2s）：停止收注，發車倒數。曝險封盤狀態在此之前隨時可能生效（§6.5）。
  • 演出（10s）：起跑 → 各賽段速度差 → 出包事件（若有）→ 衝線。演出僅播放已定賽果（§10.3）。
  • 結算（3s）：派彩、路子落新珠、生成下一輪。

Demo 範圍：以單機狀態機模擬整個 40 秒循環（本地計時器驅動狀態流轉），時間軸與正式版一致；正式版改由後台輪次調度與 WebSocket 推送驅動，前端狀態機不變（§10.4）。

§3 三屬性與賽段組成 決議② 決議③

3.1 三屬性（每局每隻隨機重生成）

屬性作用對應賽段展示
爆發直線段速度權重草地段橘色橫條 #FF8A3D
地形泥水段速度權重泥沼段＋淺灘段青色橫條 #5BC8DE
專注出包率反向（越高越不出包，§5.1）全程綠色橫條 #7BC24A

屬性每局重抽，初值取均勻分佈 30–95 待 B04。屬性條是玩家的主要判斷素材：三條長條供掃視、不放數字，「地形條長＋本局水多＝有戲」是設計要傳達的讀法。

3.2 賽段組成（每局的新題目）

賽道由草地／泥沼／淺灘三段組成，比例每局重抽並在下注畫面頂部以比例條揭示（例：草地 40%・泥沼 25%・淺灘 35%）。這是「每局變數」的來源──同一隻動物在不同賽段組成下的身價完全不同，玩家每局都有新題目可讀。

勝率權重＝屬性 × 賽段的內積：
w_i = 爆發_i × 直線占比 + 地形_i × 泥水占比（泥水占比＝泥沼＋淺灘）
名次由 w 做無放回加權抽樣決定（完整流程見 §5.2 鐵律）。心情為公式中的加減項（§4.3）。

屬性展示與實際權重：Demo 中屬性條數值直接代入權重公式（所見即所算）。正式版若後台將展示層與權重層分離，須維持展示數值與實際勝率的相關係數 > 0.9（企畫書 B-R1、驗收 §11）。

賽段比例的抽法（連續隨機重抽 vs 固定數種同 RTP 檔位）兩份文件說法不一，列 §12 開放問題 Q4；Demo 初值採連續重抽。

§4 心情機制 決議④

心情是「賽前線索」：下注時看到 😪 想睡，賽中牠真的睡著出包──「我就知道！」的讀盤成就感，也是出包側注的伏筆。機率上心情計入權重與賠率、計入 RTP，玩家不需要心算。

4.1 三種心情＋中性

徽章影響賠率連動（自動重算後標示）演出呼應
🔥 亢奮爆發 ▲（初值 +15 待 B04）勝賠下修 ▼開場暴衝、衝刺過猛
😪 想睡專注 ▼（初值 −20 待 B04）→ 出包率升該動物出包賠率下修 ▼（變易中）賽中打瞌睡（出包伏筆）
😰 怯場地形 ▼（初值 −20 待 B04）勝賠上修 ▲（視賽段組成）泥水段明顯掉速、猶豫不前
―（中性）無影響―多數動物的常態，不顯示徽章

4.2 三守則（不可違反）

  1. 已折算：心情的增減已折算進屬性條與賠率（賠率旁以 ▲▼ 標示變動方向），玩家不需自行心算。
  2. 稀疏：每局僅 2–3 隻有心情，其餘中性不顯示徽章──稀疏才是線索，全員都有徽章等於沒有資訊。
  3. 單屬性：一種心情只動一條屬性，玩家的閱讀負擔不隨機制增加。

早期示意稿在亢奮欄位註有「出包微升」，與守則③（一心情一屬性）及 §5.1（出包率僅由專注反推）不相容，列 §12 開放問題 Q5；Demo 初值採守則③從簡──亢奮只動爆發、不動出包率。

4.3 疊加條顯示規格（決稿，依路子與心情示意 Part 3）

  • 實色段＝本局實際生效值。
  • 加成（▲）：以更亮色階的延伸段接在原條之後（例：爆發橘 #FF8A3D 的加成段用亮紅 #E43D2E），基準點以 2.5px 白色分隔線標出，條末標 ▲ +15 數值。
  • 損失（▼）：原長度輪廓保留，尾端改為斜紋段（45° 斜紋，如 #F3D9D2 底＋ #D96B5B 紋）──玩家同時看到「原本多強」與「掉了多少」，條末標 ▼ −20。
  • 徽章配色：亢奮 #FFE9E0/#E45B5B、想睡 #FFF1DC/#FF8A3D、怯場 #E8F0FA/#3D74C7。

伺服端實作：心情＝權重／出包率公式中的一個加項，賽果生成流程（§5.2）與蒙地卡羅賠率反推（§6.2）自動吸收其影響、計入 RTP──模擬器照常驗證，無需特例。心情抽選規則（每局 2–3 隻怎麼抽）列 §12 開放問題 Q6。

§5 出包機制與賽果生成 決議⑤

「出包」是本作的招牌事件（爆缸的喜劇化）：動物在賽中脫線退賽。它同時是輸家的情緒出口、贏家的爽點與傳播素材──輸也有笑點。

5.1 出包率

p_out(i) = clamp( f(專注_i), 6%, 26% )──出包率由專注反向推得，夾在 [6%, 26%] 區間內。
初值公式：p_out = 0.06 + 0.20 × (95 − 專注) / 65（沿用路子模擬器）區間與曲線待 B04

心情「想睡」透過壓低專注間接抬升出包率（§4.1），不另設獨立出包修正項。

5.2 賽果生成順序（企畫書 §3-R3）

後台（Demo 為 mock-server）一次抽出完整賽果向量，嚴格依以下順序生成，不可拆成獨立事件分別定賠率：
  1. 依各隻 p_out 獨立擲骰，決定本局出包集合，並為每隻出包者擲出 out_at（出包發生的賽道位置，供演出與排序）。
  2. 從未出包集合中依權重 w（§3.2）做無放回加權抽樣，決定完賽名次。
  3. 出包者一律排在完賽者之後，彼此依 out_at 倒序（撐得越久排越前）。

出包與名次高度相關（出包者必然無法奪冠）──若把注別當獨立事件分別定價，會產生可套利組合。賠率必須由此聯合分佈反推（§6.2）。

5.3 全滅局

8 隻全數出包時，照 out_at 邏輯結算、不退款：名次＝out_at 倒序（撐最久者第 1），冠軍與前二連按此名次判定（該冠軍同時計為出包），出包注全中、零出包注全輸。此情境已包含在聯合分佈內，蒙地卡羅反推賠率時自然計入。

路子模擬器現行的全滅 fallback（將全體放回抽樣池重抽冠軍）為舊行為，與本條不符──B03 依本條實作，B06 改造模擬器時一併修正。

6.2 賠率生成（防套利方法論）

賠率表由 §5.2 的完整生成流程跑蒙地卡羅模擬（≥100 萬輪）反推各注別實際命中率，再套 賠率 = RTP / 命中率。不可用手算的邊際機率。取整方向一律對莊家有利（向下取至小數點後兩位），微幅收益計入總 RTP 對帳。
  • 心情與賽段組成改變權重 → 賠率每局重算，卡面以 ▲▼ 標示相對基準的變動方向（§4.1）。
  • 驗收須窮舉所有注別組合，驗證不存在期望值 > 100% 的組合下注策略（§11）──這是本遊戲最容易出包的地方。

6.3 冷門保護

連續 N 輪由同一隻動物奪冠時，自動微調下輪權重（企畫書 B-R4）。此為體驗保護、非勝率操控：調整量計入 RTP、作用於全體玩家、不讀取任何玩家個人維度資料（合規要求，企畫書 §7）。N 與調整量 待 B04。

6.4 大滿貫獎池（是否納入 Demo 未定）

示意稿下注畫面含「🏆 大滿貫獎池」跑馬燈；任務板將獎池列為「若後續加」的繼承資產（chainfire 分級派發公式可直接沿用）。是否納入 Demo 列 §12 開放問題 Q8。

6.5 曝險封盤

單一注別達曝險上限時該注別轉不可押（available: false），文案一律用「本輪額度已滿」而非「禁止下注」。Demo 僅保留接口與 UI 狀態，不實作額度邏輯。

§7 路子系統 決議⑦

路子是延長遊玩時長與大廳圍觀感的核心元件。冠軍是 8 選 1、無法直接套百家樂路，解法是把賽果做二元投影之後套用標準路子演算法──大路、大眼仔、小路、蟑螂路原封不動。本節的頁籤結構、版位尺寸、互動規格一律以路子模擬器（活原型）為準。

7.1 版位

  • 下注階段（25s）演出區閒置，直接顯示路子總覽──一打開就看到全紀錄，不多一層導航。
  • 開賽自動切回賽事畫面；賽後回到總覽並落下新珠（有落珠動畫）。
  • 全服輪次不論是否下注均記錄。手機直式下總覽為整版、其餘路頁籤切換；平板／橫式可並排。

7.3 總覽珠盤與「出包不設二元路」

  • 讀法：一局一珠、由上往下填、滿 6 珠換下一列（時間往右），與百家樂珠盤相同。
  • 冠軍模式：珠色＝冠軍動物固定色＋編號（小兔淺色珠加描邊）；角標＝該局出包隻數：1–3 隻為橘點 #FF8A3D 疊標，≥4 隻改紅底數字徽章 #E43D2E。
  • 出包計數模式：珠面直接顯示隻數，0＝灰框／1＝黃框／2＝橘框／3+＝紅實心。
  • 點單珠＝開啟該局詳情彈窗（7.6）。
出包不設二元路：有出包／零出包的分佈偏斜約 3:1，二元路會長期單邊、沒有讀路價值。出包資訊改由三處承擔──總覽角標（多不多）、出包計數模式（幾隻）、動物卡個體統計（誰常出包，§8）；「是誰」放詳情彈窗。

7.5 互動規格（含已修 bug 的實作鐵則）

  • 各路子容器拖曳平移（隱藏捲軸）；預設停在最右端（最新）。
  • 頁籤切換後須在面板顯示之後才執行捲到最新──面板隱藏時 scrollWidth 取不到。
  • 位移 > 5px 判定為拖曳，並在捕獲階段抑制後續 click（避免拖完誤觸切換／彈窗）。
拖曳實作不可使用 setPointerCapture──它會把 click 目標劫持到容器，害珠盤的「點擊切換模式」收不到事件（模擬器已踩過並修正）。正確做法：pointerdown 掛在容器上，pointermove／pointerup／pointercancel 監聽 window。

7.6 點珠詳情彈窗

總覽答「趨勢」，詳情答「這局到底發生什麼」。點珠盤任一珠彈出：

  1. 標題列：局號＋時間（主色底 #2E6B8A）。
  2. 本局賽段：草地／泥沼／淺灘比例條──這局的「題目」。
  3. 完整名次：冠軍列金底高亮（含奪冠原因短註，例「水段起飛」）；各列含編號珠、名稱、當局心情註記（例「🔥亢奮（爆發+15）」）。
  4. 出包者沉底橘列：依 out_at 倒序；含出包地點（哪個賽段）、心情伏筆回收（「😪想睡 → 草地段睡著」）、該注賠率與 ✓（有玩家中此注）。
  5. 左右滑動看上一局／下一局；點動物名看牠的近期走勢（§8）；點外圍或 ✕ 一步回總覽。

7.7 資料保留量

【已裁決 2026-09-01】路子每 200 局重置（沿龍虎鬥「換靴」慣例，原對應撲克牌靴量）：靴內全量保留、滿 200 局清空重計、介面標「第 N 靴」；靴內渲染視窗由 B06 依版位定。原 96／120／160 之爭作廢。

§8 個體統計 決議⑨

每張動物卡常駐「近 20 局：勝 x・包 y」。原則：側注決策資訊出現在做決策的位置──押「小兔出包」的人要的是小兔的出包頻率，不是全場的，不必去路子裡翻。點卡可展開該動物的近期走勢（勝／包／名次折線）。統計由全服輪次流累計（不論玩家是否下注）。

  • 心情演出呼應：想睡的在賽中打瞌睡、亢奮的開場暴衝──下注時的徽章在演出中兌現。
  • 演出時長規範見 §5.4 註；演出僅為已定賽果的播放（§10.3）。

§10 系統架構與資料流

10.1 兩層架構

可移植邏輯層（純函數、無 DOM，可轉 Cocos／Unity）

  • round-engine：40 秒輪次狀態機（betting → locked → racing → settled）
  • result-gen：屬性／賽段／心情生成＋ §5.2 聯合分佈賽果抽樣
  • odds-mc：蒙地卡羅賠率反推（§6.2）
  • settle：注單結算（含全滅局規則）
  • roads：二元投影＋大路／衍生路演算法（自路子模擬器抽出）
  • stats：近 20 局個體統計、路子保留窗

拋棄式演出層（HTML Demo 專用，換引擎即重寫）

  • 下注 UI、動物卡、疊加條渲染
  • 賽事演出（跑動、出包喜劇、衝線）
  • 路子繪製與拖曳互動（§7.5）
  • 詳情彈窗、派彩與落珠動畫

演出層只讀 outcome 與演出腳本，不持有任何影響結果的邏輯。

10.3 結算與演出分離（企畫書 §1.1，全案前提）

  • 賽果在封盤當下一次性決定完畢；演出只是把已定結果播出來。
  • 前端不持有任何影響結果的邏輯──反編譯只能提前知道結果、無法改變結果。
  • 結果封包一次下發完整內容，不逐段請求。
  • 斷線重連還原至原狀態、不重播演出（Demo 可簡化，正式版必備 round/pending）。

10.4 契約形狀（Demo mock ＝ 正式版接口的子集，沿企畫書 §5.4 改欄名）

// 開局下發（正式版 GET /round/current ＋ WebSocket 推送）
round = {
  round_no, state,            // betting | locked | racing | settled
  betting_ends_at,
  segments: { grass: 0.40, mud: 0.25, water: 0.35 },   // 每局重抽
  animals: [{
    id, name,
    attrs: { burst, terrain, focus },                  // 本局屬性（含心情折算前原值）
    mood:  null | "hyper" | "sleepy" | "nervous",      // 中性為 null，每局僅 2–3 隻非空
    mood_delta,                                        // 疊加條用：±幅度
    stats20: { wins, outs },                           // 近 20 局個體統計
    odds: { win, out },                                // 每局重算，含 ▲▼ 基準比對值
    available: { win: true, out: true }                // 曝險封盤 → false
  } × 8],
  odds_exacta: { "1-2": 6.50, … },                     // 前二連 28 組合（不計順序）
  odds_no_out: 2.60
}

// 賽果（封盤時一次抽定，演出開始前已下發）
outcome = {
  round_no,
  ranking: [id × 8],          // 完整名次（出包者沉底、依 out_at 倒序）
  out:     [bool × 8],        // 出包旗標（索引＝動物 id − 1）
  out_at:  [int × 8],         // 出包位置（公尺；未出包＝0；演出與沉底排序用）
  payouts: [{ bet_index, hit, payout }],
  total_payout
}

Demo 範圍：以上全部由單機 mock-server（本地 RNG）供給，無網路；正式版把 round 改為後台推送、outcome 改為結算下發，欄位形狀不變──這是留給後台團隊的接口草案。

10.5 繼承資產（chainfire）

結算／演出分離架構、mock 契約形狀、sim-engine 驗證器、輪次／狀態機模式、獎池分級公式（若加獎池）、路子模擬器（B06 直接改造）。

§11 驗收要點（B04 數值驗證／B09 整合驗收）

  1. RTP：蒙地卡羅 100 萬輪，四種注別實測 RTP 各自落在目標值 ±0.1%。
  2. 防套利：窮舉所有注別組合（含跨注別複押），驗證不存在期望值 > 100% 的組合策略。本遊戲最容易出事的地方。
  3. 展示與勝率一致：屬性展示值與實際勝率相關係數 > 0.9。
  4. 全滅局：8 隻全出包時依 §5.3 結算正確、不退款；出現頻率與理論值相符。
  5. 路子均衡度：大小／奇偶長期接近 50/50；冷熱守住率落在可玩帶（門檻由 B04 校定）；大冷門出現率有感但稀有。
  6. 出包計數分佈：有出包：零出包偏斜比與 ~3:1 假設核對（支持 §7.3 不設二元路的前提）。
  7. 輪次時序：40 秒循環各階段準時，演出不溢出 10 秒（含全滅局與多出包局）。
  8. 路子互動：拖曳不劫持點擊（§7.5 鐵則）、頁籤切換後停在最新、觸控與滑鼠皆測。
