# 爆金連鎖｜HTML Demo（v3）

點一格丟一枚幣，疊到 4 枚就炸開、往四邊各噴 1 枚，隔壁滿了跟著炸；**噴出盤面的都是你的**（普通幣 0.5 個面額，100 面額＝50）。每丟一枚＝一注（注額＝底部選的金額 100／500／1,000）。**只有一張盤面**：盤面、**能量條**、**連鎖獎池**都留著；每丟一枚能量條漲一格，集滿 100 格那一注，玩家那一枚連爆完後下**金幣雨**——25 格各同時落下一枚免費普通幣、再連爆到穩定。獎池每丟一枚存 0.15 個面額（100 面額＝15）；自己丟的那一枚一次連爆到 8 格以上（或下金幣雨）就把獎池整個拿走、歸零重來。連爆過程中每炸一格跳一次 **Combo** 數字，數到 8 在盤面中上方放大彈出並接上拿獎池的演出。鑽石、皇冠是加料（丟出來有機率是寶物，被擠出盤面才兌現）。**v3 新增兩個操作**：**刷新盤面**（同枚數、同寶物、換個位置，要確認，之後隔 10 注才能再刷）與**換金額**（盤面換成全新 40 枚、能量條與獎池歸零、寶物消失，要確認）。RTP 94.94%（`node test/mc-test.js` 驗過）。手機直式 375×812。

## 運行方式

零依賴、零建置、無 ES Modules、無 Web Worker、無 fetch，普通 `<script>` 串接。

- 雙擊 `index.html`（`file://` 直開）即可遊玩，資料存在瀏覽器 localStorage。
- 數值自測：`node test/mc-test.js [N]`（Node 20+，無需套件）；核心單元回歸：`node test/core-test.js`（PASS 174／FAIL 0）。
- 起始盤面：`node test/find-start.js`（固定種子搜尋，`--write` 才寫回 `values.js`）。

## 玩法與介面

| 東西 | 說明 |
|---|---|
| 點格子 | 丟一枚（＝下注）；第一次進場只有一格發光可點，其他變暗 |
| 疊 3 枚的格子 | 金色底＝快滿；相鄰兩格都快滿＝中間連起來、會一起炸 |
| 提示（頂欄燈泡鈕；預設開，存 `burst.hint`） | 每個疊 3 枚的格子角上一顆小徽章＝「點下去會炸幾格」（`EV.probe`，核心驗過等於真丟普通幣的連爆格數；丟鑽石、皇冠格數相同）。深藍底＝一般；金邊＝已到門檻一半；**爆炸徽章＋格子描邊＝炸得到 8 格、能拿獎池**。演出中隱藏、演出完才出現（刷新、換金額演完也會照新盤面重算）；第一次進場不顯示；關掉後畫面上沒有任何提示數字 |
| 金額鈕（底部一整列 100／500／1,000） | 選中亮金。點別顆 → **確認視窗**逐項寫清楚會放棄什麼：盤面換新（40 枚、沒有寶物）、能量條歸零、獎池（有錢標「放棄 N」、沒錢標「歸零」）、寶物消失（盤上有寶物才列）；確認才換（換盤約 0.4 秒，能量條與獎池同時滾動歸零），錢包不動。換金額不產生紀錄。演出中、自動下注中、第一次進場時點了不開窗 |
| 刷新鈕（自動鈕左邊的圓鈕） | 可刷＝藍底＋換位圖示；冷卻＝灰、金色外圈進度、中間寫還要幾注。點可刷的鈕 → **確認視窗**（幣數不變、寶物保留、能量條不動、獎池不動、「下次刷新要隔 10 注」）→ 確認才刷（換盤約 0.5 秒）。刷新抽 24 張同枚數的合法盤面，取「現在點下去能炸最多格」的那張；冷卻每丟一注減 1。冷卻中點它只 toast「再 N 注才能刷新」。演出中、自動下注中、第一次進場時點了不開窗。刷新不產生紀錄 |
| 獎池（收集槽下方，爆炸徽章＋金額） | 目前的獎池，每丟一枚跳一下（冒 +15／+75／+150）；上限 15 個面額（金額 ×15）；徽章裡的數字是「炸幾格拿走」。拿到時（連鎖演完／雨演完之後）：獎池蓄力 → 整筆化成一張橘金牌飛進收集槽的金額（獎池數字倒數到 0）→ 金額一次大跳 → 隨落袋整筆飛進錢包，獎池從 0 重來 |
| Combo（連爆中，跳在爆炸的那一格右上角） | 每炸一格跳一次累計數字（同格炸兩次算兩格），圖案沿用提示與獎池的橘色爆炸徽章；每一波最新一顆最大並帶「Combo」字樣，下一波來時前一顆縮小淡出；**數到 8（`EV.POT_CHAIN`）在盤面中上方放大彈出**，獎池同時跳一下、接著拿獎池演出。金幣雨那一段另外從 1 數（藍金色、雨滴字樣）、不觸發 8 的放大。只炸 1 格不顯示 |
| 能量條（頂欄下，100 格） | 被金幣填滿的橫條，不寫數字；每丟一枚漲一格；剩 4 格以內＝快滿（金框脈動、雨雲徽章轉金）；**換金額歸零，刷新不動** |
| 圖例（獎池右邊一行淡色小字，不是按鈕） | 「圖示＝數字」：金幣 50／鑽石 500／皇冠 5,000（隨金額變）；沒有外框、沒有底色、點不到，避免和金額鈕混淆 |
| 寶物（鑽石／皇冠） | 停在盤上時有箭頭指它下次往哪邊走；被擠出盤面才兌現；刷新保留（換位置）、換金額消失 |
| 金幣雨 | 能量條集滿 100 格的那一注：玩家那一枚（含連鎖）結算完 → 預告 → 25 格各落一枚免費普通幣 → 連爆到穩定；雨那一注的拿回是整場合計（含獎池：雨一定把獎池帶走），能量條歸零；落下的 25 枚沒收錢（成本攤在每枚普通幣的 0.5 裡）。雨帶出的連鎖不算進「炸 8 格」 |
| 速度鈕（雙箭頭） | 普通／高速（約 0.6 倍時間），存 `burst.speed` |
| 自動 | 丟法／局數／停利／停損四項。局數 10／50／100／不限（不限＝只靠停利、停損、餘額不足或手動停止）。丟法兩種：**8 格引爆**（有格子現在點下去能炸 8 格以上就點炸最多的那格、拿獎池；沒有就丟在疊 2 枚的格子養盤，沒有 2 枚就 1 枚、再沒有就空格）、**快速回收**（有疊 3 枚的格子就從中隨機挑一格，沒有就 25 格隨機一格）；沿用目前的金額與盤面（彈窗沒有「單注」列，注額一律是目前金額，換過金額再開也對得上）與速度；**自動下注不會自己刷新、不會自己換金額**；到局數、達停利或停損、餘額不足會停；重整頁面也會中止；進行中手點格子、金額鈕、刷新鈕都會被擋（toast「自動下注中，請先停止」、不開確認窗）。金幣雨與拿獎池的那一局要等整場演完才下一局，雨與獎池的拿回（含獎池）算進累計輸贏（停利停損看得到） |
| 紀錄 | 一注一筆、最近 50 筆（**刷新與換金額不是一注，不產生紀錄**）；總覽顯示淨額（拿回−下注），**淨額 >0 金色、≤0 灰色**（有拿回但沒回本、剛好回本的 ±0 都是灰）；詳細頁列：面額、拿回、獎池（拿了才有；「拿回」是含獎池的總額，總覽的輸贏淨額也含獎池）、丟在哪格、丟的是什麼、連爆幾格、噴出什麼；下雨的那一注多一列「其中金幣雨帶出」。連爆、噴出是整注合計（玩家那一枚＋金幣雨），「其中金幣雨帶出」是合計裡雨那一段（含在噴出裡，不是另外加）；底列「重置錢包」二段確認（只把錢包補回 10,000、紀錄清空；**盤面、能量條、獎池、冷卻、金額都不動**） |

## script 載入順序（固定）

`values.js → js/env.js → js/strings.js → js/toast.js → js/core.js → js/drag-scroll.js → js/log-ui.js → js/autobet.js → js/art.js → js/fx.js → js/ui-main.js → js/wire.js → js/dev.js`

- `values.js` 最先（只有 `EV`、`DEMO_KEY`，零依賴）；`env.js` 建 `DEMO` 命名空間與 `DEMO.ls`，之後每支都靠它。
- `strings.js` 必須早於所有 UI 檔（它在載入當下把骨架的 `data-t` 填好）。
- `core.js` 只依賴 `values.js`（Node 測試即 eval 這兩支）。
- `log-ui`／`autobet` 彼此不認識玩法；`ui-main.js` 建主畫面與 `DEMO.ui`，`wire.js` 把兩個模組接到 `DEMO.ui`／核心，`dev.js` 最後載入（導演台、截圖駕駛、預設網址收尾）。
- 樣式：`css/base.css` 最先（變數與疊層順序表），其餘模組樣式在後；`css/wire.css` 蓋過這款需要的差異。`onboard.js`／`onboard.css` 這款不用（不做教學），檔案保留、不引用。

## 數值紀律（改東西前先讀）

- **禁手改單點**：所有賠率、上限都由 `values.js` 的 `CFG` 推導；其他檔案嚴禁硬編碼賠率或機率。
- **嚴禁暗改機率 p**（抽獎與賠率都吃它）；要調 RTP 只准動賠率表。
- 結果先由核心抽定，UI 只負責演；演完 `ack()` 才結算。導演台只包 rng／指定下一注／改能量條與獎池與冷卻，不動賠率。
- 刷新與換金額用**另一串盤面亂數**，不影響之後每一注抽到什麼幣。
- 自動選格只看盤面上每格幾枚，以及「會炸幾格」（和畫面提示同一個數字）；不預看這一枚是什麼、不用核心 rng。
- 金額全部整數（Demo）。
- 效能紅線：所有 transition／animation 只動 `transform`／`opacity`；禁 `filter`；陰影靜態。目標裝置含舊手機。
- 零捲軸：#app 任何狀態 `scrollWidth/Height` 都不得大於 `clientWidth/Height`——待命的彈窗／頁面不可用 translate 推到 #app 外，改用 `opacity`＋小幅 `scale` 淡入。
- 所有面向玩家的字串走 `t()`，做新字串後跑一次 `?lang=xx` 看有沒有破版。

## Demo 補充假設

- 後台、錢包、注單號、時間皆為本地模擬：注單號由前綴＋時間＋流水號組成，不是真後端單號；亂數用瀏覽器的 `Math.random`，不是後台抽獎。
- 「回報」鈕只 toast，不會真的送出。
- 錢包與 log 存在瀏覽器 localStorage，清除瀏覽器資料即歸零。
- 金額全部整數；正式版要讓玩家輸入金額、支援小數（金額鈕的 100／500／1,000 只是暫定三檔，未來正式版需要能調整）。
- **能量條預充 70（`DemoCore.METER_START`）是 Demo 專用**：新玩家丟 30 注就看得到第一場金幣雨（70＋30＝100）；正式版應從 0 起算，長期 RTP 不受影響（只是起點不同）。只給帳號的第一張盤面；**換金額後能量條從 0 開始，不再預充**。
- **理論 RTP＝(1−1/40−1/800＋25/100)×0.5＋0.125＋0.0625＋0.15＝94.94%**（比舊版 96.97% 低，因為金幣雨從 86 注改 100 注）。獎池每注存 0.15 個面額、遲早全數發還，所以長期拿回與丟法無關。
- **刷新不能套利**：幣數與寶物不增不減、合法盤面（守得住最低 40 枚）、能量條與獎池不動、冷卻 10 注；刷新與抽獎用不同亂數串。模擬：不刷／每注都刷／沒到 8 格就刷，同一串亂數拿回都是 94.77%（見 `reports/規格書_v3.html`）。
- **換金額不能套利**：換金額＝盤面換成新的 40 枚（無寶物）、能量條歸零（不預充）、獎池歸零，錢包不補不退；放棄的東西在確認視窗寫清楚。重新整理頁面會接回同一張盤面（演出中那一注直接結算），刷不到錢。
- **重置錢包只在 Demo**：只把錢包補回 10,000、紀錄清空；**盤面、能量條、獎池、冷卻、金額都不動**，只是為了沒錢時能繼續測試；正式版沒有。
- 面額 100／500／1,000 為暫定；起始錢包 10,000 是假的。
- 美術（金幣、鑽石、皇冠、盤面）全部程式畫的佔位，沒有外部圖；沒有音效。
- 自動下注的停利／停損／局數選項是 Demo 暫定值；自動選格規則是用戶定案（有疊 3 枚的格子就丟其中一格、沒有就隨機；8 格引爆為養盤到門檻才引爆）。
- 導演台（`?dev=1`）與 `?shot=` 只為了測試與截圖，不進正式版；能改能量條（`setMeter`）、獎池（`setPot`）、冷卻（`setRefreshLeft`）、加錢的入口只有導演台，預設網址沒有。

## 預設網址擋了什麼、沒擋什麼

逐項（探針 `default-url.js`／`default-hack.js` 驗過，不帶 `?dev`／`?shot`）：

- 擋了：沒有導演台、沒有 `DEMO.game`／`DEMO.dev`／`DEMO.shots`（所以 console 指定不了結果〔`setRng`／`armNext`〕、設不了能量條〔`setMeter`〕與獎池〔`setPot`〕、清不了刷新冷卻〔`setRefreshLeft`〕、加不了錢〔`addMoney`〕、改不了盤面亂數〔`setBoardRng`〕）；`DEMO.ui.setDenom`（直接換金額、不跳確認、會繞過自動下注的鎖的相容掛點）在預設網址被拿掉，只剩玩家手點的 `askDenom`（先確認）；`DEMO.ui.play` 的指定結果參數不認（載入時就定好，事後改 `DEMO.q.dev` 或 `DEMO.q.shot` 也沒用）；`DEMO.ui`／`DEMO.wire` 的鍵裡沒有改核心狀態的名字。
- 合法路徑仍守規則：刷新只能點鈕→確認，冷卻中 `askRefresh` 開不了窗，冷卻只會隨下注倒數（重整頁面也清不掉：存檔裡有）；換金額只能點金額鈕→確認。
- 沒擋（Demo 擋不了，結果在瀏覽器裡算、存檔在 localStorage）：懂的人仍可從 console 另建一個核心（`DemoCore.createGame()`）加錢或改能量條、獎池、冷卻、改寫 `EV`／`DemoCore.RULES` 的函式、或直接改 `localStorage` 的存檔。正式版結果與錢包都在後台，這些都不存在。
- 同時開兩個分頁玩同一個存檔，後存的會蓋掉先存的（不會重複入帳）。
- 存檔鍵 `burst.gen`：換版記號（`ui-main.js` 的 `SAVE_GEN`，目前 6）。和程式裡的不同時，會清掉舊的紀錄與「看過第一次進場」的記號；核心存檔 `v:6` 以外的版本整份忽略。
